# ZMouseShow 需求规格说明书

文档版本：0.8（P4 候选实现完成）
目标平台：Windows 10 2004（Build 19041）及以上、Windows 11，x64  
构建环境：Visual Studio 2026、MSVC v145、CMake 4.4、C++23

## 1. 项目目标

ZMouseShow 是一个免安装、无管理员权限运行的 Windows 鼠标定位工具，主要解决笔记本连接多块高分辨率显示器后难以快速发现鼠标位置的问题。

程序通过纯净的双击左 Ctrl 手势或快速晃动鼠标触发定位效果：所有显示器短暂暗化，鼠标周围保留原始亮度，并显示醒目的脉冲效果。

### 1.1 核心目标

- 发布为原生 x64 单文件 `ZMouseShow.exe`。
- 不安装服务，不要求管理员权限，不写入 HKLM 注册表。
- 不依赖 .NET、WinUI Runtime、VC++ Redistributable 或第三方运行时 DLL。
- 正常输入必须继续传递给前台应用，程序不得拦截或修改键鼠事件。
- 适配负坐标、多显示器、混合 DPI、显示器热插拔和不同刷新率。
- 不记录按键内容、鼠标轨迹或遥测数据。

Windows 自带的系统 DLL 和图形组件不视为外部运行时依赖。

### 1.2 非目标

首个版本不承诺支持以下场景：

- UAC 安全桌面、锁屏界面和 `Ctrl+Alt+Del` 安全注意序列界面。
- 独占全屏程序、受保护视频内容或禁止桌面叠加的程序。
- 被企业 WDAC、AppLocker 或终端安全软件策略禁止执行未知 EXE 的环境。
- ARM64、Windows 10 Build 19041 以前的系统。
- 真正替换系统光标或修改系统光标方案。

## 2. 用户场景

典型环境为笔记本内屏加两块 2K、120Hz 外接显示器。显示器可能具有不同 DPI 缩放比例、不同刷新率，且主显示器不一定处于虚拟桌面的左上角。

程序应在普通用户权限下直接双击运行，驻留系统托盘。用户无需先创建配置文件即可使用默认行为。

### 3.2 输入监听原则

键盘和鼠标输入使用 Raw Input（`WM_INPUT` + `RIDEV_INPUTSINK`）在后台观察，不使用 `WH_KEYBOARD_LL` 或 `WH_MOUSE_LL` 全局低级钩子。

- 不使用 `RIDEV_NOLEGACY`，不得阻止前台应用接收原始输入。
- 只在内存中维护当前按键/鼠标按钮状态、手势状态和短期相对位移。
- 不保存键值序列，不将输入写入日志或配置文件。
- 输入处理和渲染状态通过消息或事件解耦，Raw Input 处理不得执行耗时绘制。

### 3.3 双击 Ctrl 触发

默认启用左 Ctrl；P1 可通过配置选择左 Ctrl、右 Ctrl 或任一侧。合法手势为：

```text
选定侧 Ctrl 按下 → 同侧 Ctrl 释放 → 同侧 Ctrl 按下（触发）→ 同侧 Ctrl 释放
```

必须同时满足：

- 第一次 Ctrl 按下前，没有其他键或任何鼠标按钮处于按下状态。
- 两次按键必须来自同一侧；即使配置为任一侧，左右 Ctrl 混用也不得触发。
- 两次按下间隔不超过系统 `GetDoubleClickTime()`，且不短于防抖下限。
- 手势期间没有其他键盘按键或鼠标按钮事件。
- 忽略键盘自动重复产生的重复按下事件。
- 触发后进入短暂冷却期，避免同一手势重复触发。

下列输入必须取消候选手势：

- `Ctrl+C`、`Ctrl+V`、`Ctrl+Shift+...` 等组合键。
- Alt、Win、未选定侧 Ctrl 或任意普通按键参与的输入。
- 左键、右键、中键、X1 或 X2 鼠标按钮按下。
- 第一、第二次 Ctrl 之间出现鼠标按钮事件。

取消候选手势不得吞掉或改变任何输入。触发手势残留的 Ctrl 释放事件不得立即关闭刚显示的 Overlay。

### 3.4 自定义组合键触发

P1 支持一个默认关闭的自定义组合键。按键支持 `A`–`Z`、`0`–`9` 和 `F1`–`F24`，并可分别要求 Ctrl、Alt、Shift、Win；其中 F12 因 Windows 调试器保留而拒绝注册。只有当前修饰键状态与配置完全一致、没有其他普通键按下且主键不是自动重复时才能触发；组合键残留的释放事件不得立即关闭 Overlay。默认组合为 `Ctrl+Alt+F11`，但只有显式启用后生效。

P2 中双击 Ctrl、自定义组合键和晃动鼠标作为独立触发源，不强制互斥。快捷键配置必须整组验证；设置面板先探测系统级占用，运行时持续注册生效的组合键。字段非法、保存失败或检测到不可接受的全局冲突时，保留上一组有效配置或仅禁用自定义组合键，不得静默启用另一组用户未确认的组合键。

### 3.5 晃动鼠标触发

首个公开测试版本默认关闭，用户可在配置中启用。经过真实鼠标和触控板验证后再决定是否默认开启。

晃动检测使用 Raw Input 相对位移的滑动时间窗口，不使用单纯的屏幕像素位移阈值。判定至少考虑：

- 时间窗口内累计路径长度。
- 移动轨迹包围盒对角线。
- 累计路径与包围盒对角线的比值。
- 水平或垂直方向反转次数。
- 触发后的冷却时间。

以下情况禁止触发：

- 左、右、中、X1、X2 任意鼠标按钮处于按下状态。
- 任意鼠标按钮按下或释放的当前轨迹段。
- Overlay 已处于显示或淡出状态。
- 已有 Ctrl、自定义组合键或晃动触发请求等待主消息循环激活 Overlay。
- 程序处于暂停状态。

任意鼠标按钮按下时必须立即清空晃动历史。全部按钮释放后也必须从新的移动轨迹开始累计，不能继承拖拽期间的位移。

### 3.6 定位效果

P0 默认效果为：

1. 所有有效显示器暗化。
2. 鼠标周围出现真正透明的高亮孔，默认使用圆形，显示下面窗口的原始亮度。
3. 高亮孔周围显示与孔洞同形状的稳定高对比度描边，并在触发瞬间显示同形状、向外扩散且逐渐淡出的波纹。
4. 效果淡入并跟随鼠标。
5. 默认持续显示，直到用户按键、点击、滚轮、暂停或退出；可选启用静止自动淡出和最大显示时长保护。

默认建议值：

| 设置 | 默认值 | 单位/说明 |
| --- | --- | --- |
| 高亮形状 | 圆形 | 可选圆形、圆角方形或菱形 |
| 高亮半径 | 120 | DIP，按显示器 DPI 转换为物理像素 |
| 暗化不透明度 | 60 | 百分比 |
| 淡入/淡出时长 | 220 | ms |
| 自动关闭 | false | 默认关闭，便于长时间强调鼠标位置 |
| 静止自动关闭 | 1200 | ms |
| 最大显示时长 | 5000 | ms |
| 高亮描边 | true | 与高亮孔同形状，可独立关闭 |
| 启动波纹 | true | 从高亮半径向外扩散至 1.75 倍并淡出 |
| 十字定位线 | false | 默认关闭；使用深色外沿与浅色内芯 |
| 放大光标 | false | 默认关闭，默认倍率 200%；启用时只显示一个指针 |

下列行为立即启动淡出：

- Esc。
- 任意非触发键盘按键。
- 任意鼠标按钮按下；点击必须继续传递给下层窗口。
- 达到静止时间或最大显示时间。

触发手势自身剩余的 Ctrl 或自定义组合键释放事件不得立即关闭刚显示的效果。

### 3.7 可选视觉效果

| 效果 | 方案 | 优先级 |
| --- | --- | --- |
| 放大光标 | 通过 `GetCursorInfo` 获取当前 `HCURSOR`，根据黑底/白底两次绘制重建预乘 Alpha，在独立分层窗口中绘制；显示期间临时隐藏原光标，正常隐藏、退出和失败路径恢复。 | P3 已实现 |
| 波纹 | 从鼠标位置扩散并淡出；与稳定描边分别栅格化，形状跟随孔洞，可独立关闭。 | P3 已实现 |
| 十字定位线 | 在鼠标所在显示器绘制带深色外沿和浅色内芯的高对比度定位线。 | P3 已实现 |
| 局部内容放大镜 | 捕获并放大鼠标附近屏幕内容，默认包含指针；可与暗化遮罩组合，也可独立显示。 | P4 候选 |

不得通过 `SetSystemCursor` 修改全局系统光标。

透明高亮区域支持圆形、圆角方形和菱形预设，默认保持圆形。高亮描边和波纹跟随孔洞形状；十字定位线与放大光标仍是独立效果。

### 3.8 诊断信息导出

P1 托盘菜单提供“导出诊断信息”，覆盖写入当前配置目录下的 `ZMouseShow-diagnostics.txt`；运行第二个 `ZMouseShow.exe --diagnostics` 也可请求现有实例执行同一操作。报告至少包含程序版本与构建类型、配置路径、暂停状态、触发请求/Overlay/托盘菜单/设置窗口活动状态、当前有效配置、自定义组合键的本次运行注册状态、虚拟桌面边界，以及每块显示器的设备名、边界、工作区、有效 DPI 和主屏标记。报告不得包含按键历史、鼠标当前或历史坐标、鼠标移动轨迹或屏幕内容；导出失败只通过托盘通知提示，不阻塞程序。

### 3.9 应用排除与全屏抑制

“全屏抑制”是前台窗口启发式策略，不等同于游戏识别：

- `off`：不因全屏状态抑制触发。
- `automatic`：前台窗口覆盖其所在显示器，或系统指针被限制在小于虚拟桌面的区域时，只抑制鼠标晃动；双击 Ctrl 和自定义组合键仍可明确唤醒。
- `strict`：上述沉浸状态下抑制全部触发。

应用排除按前台进程的 EXE 文件名进行不区分 ASCII 大小写的精确匹配，并优先于全屏策略抑制全部触发。列表不得包含路径，最多 64 项。查询前台进程失败时不得误判为已排除。

登录自启动通过 `HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Run` 的 `ZMouseShow` 值实现，只影响当前用户且不要求管理员权限。设置保存失败时回滚本次注册修改；注册表写入被企业策略拒绝时保持程序运行并提示失败。

## 4. Overlay 与渲染设计

### 4.1 窗口模型

- 每个有效显示器创建一个独立 Overlay 窗口。
- 窗口使用 `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW | WS_EX_TRANSPARENT | WS_EX_LAYERED`。
- 通过 `HWND_TOPMOST` 显示，不激活窗口；`WM_NCHITTEST` 返回 `HTTRANSPARENT`。
- 所有坐标在 Per-Monitor V2 感知下使用物理屏幕坐标，并显式处理虚拟桌面负坐标。
- 显示器拓扑变化后重新枚举显示器并原子替换窗口集合。

Windows 任务栏自身可能处于 Topmost 层级。任务栏刚被用户激活时，Shell 可能把它维持在暗化窗口之前；程序不得为保证覆盖而抢占前台焦点、隐藏任务栏、操作 Explorer 或调用未公开窗口层级 API。

### 4.2 P0 混合渲染后端

首选技术验证方案：Window Region + 小型 per-pixel alpha 位图。

- 每块显示器使用恒定透明度的黑色 Overlay。
- 使用 Window Region 从 Overlay 中减去鼠标附近的预设高亮形状。
- 高亮孔基础区域不需要显示器大小的 32 位位图。
- 仅为高亮孔边缘、羽化和脉冲环维护一张数百像素大小的分层位图。
- 鼠标位于显示器边界时，对所有相交显示器应用相同全局高亮孔。

必须先通过技术验证确认：

- Region 动画不存在明显闪烁或任务栏异常。
- 圆孔跨显示器边缘时没有明显接缝。
- 混合 DPI 和负坐标下圆心一致。
- 60Hz/120Hz 混合环境下动画节奏可接受。

如果该方案达不到视觉质量要求，保留相同的 Overlay 管理接口，替换为 Direct2D + DirectComposition 后端。不得直接依赖 WinUI 3 或 Windows App SDK Composition。

### 4.3 不采用全屏 GDI+ 位图的原因

三块 2560×1440 显示器横排时，单张 32 位虚拟桌面位图约占 42MiB；双缓冲、GDI 对象和逐帧内存复制会进一步增加资源消耗。全屏 `UpdateLayeredWindow` 不作为正式渲染方案。

## 5. 配置机制

P0/P1 使用内置默认值和可选 TOML 文件；P2 在其上提供原生设置对话框，TOML 仍是完整配置的单一持久化来源。

### 5.1 配置加载规则

- 未找到配置文件：使用全部内置默认值。
- 空配置文件：使用全部内置默认值。
- 缺失字段：使用该字段的内置默认值。
- 字段类型错误或数值越界：忽略该字段并使用默认值。
- TOML 语法错误：拒绝整份文件；启动时使用内置默认值，重新加载时保留当前配置。
- 重新加载失败：保留上一次完整有效配置。
- 未知字段：忽略，以支持前向兼容。
- 程序不得因为配置错误而退出或显示阻塞式错误框。

配置查找顺序：

1. 命令行 `--config <path>` 指定文件。
2. EXE 同目录的 `ZMouseShow.toml`。
3. 内置默认值。

程序首次运行不主动创建文件。托盘“导出默认配置”由用户显式触发；用户在托盘或设置对话框修改可持久化选项时，程序创建或更新当前配置文件。写回采用同目录临时文件加原子替换，只修改对应字段并保留注释与未知字段。“暂停”仅对本次运行有效，不持久化。

### 5.2 设置界面

P2 首批实现原生 Win32 模态设置对话框，不引入 WinUI、WPF、WebView 或外部运行时。可从托盘“设置”或命令行 `--settings` 打开，并遵循系统字体、键盘访问键和“确定 / 取消 / 应用”的标准交互。

首批面板覆盖：

- 启用鼠标晃动触发；启用后可用 1–10 灵敏度滑条调整累计位移阈值，默认 5 对应 `minimum_distance = 1000.0`。
- 双击 Ctrl 的左侧、右侧或任一侧选择。
- 启用自定义组合键，通过原生 Hot Key 控件录入 Ctrl、Alt、Shift 与主键，并可单独包含 Win；提供恢复默认、合法性检查、常用组合警告和系统级占用探测。
- 启用自动超时。
- 高亮形状、高亮半径与暗化强度；数值在保存前执行范围校验。
- 高亮描边、启动波纹、十字定位线、放大光标及其倍率。
- 全屏抑制模式、应用排除列表和当前用户登录自启动。
- 恢复默认配置；操作先更新对话框草稿，应用或确定后才持久化，取消可放弃。

“应用”与“确定”先原子保存 TOML，成功后再更新当前运行时；保存失败时保持原配置和运行时状态。“取消”放弃尚未应用的修改；已经应用的修改不回滚。当前对话框以独立顶层窗口显示，因为常驻托盘的隐藏 `WS_EX_NOACTIVATE` 窗口不能作为其可见 owner。

## 6. 非功能性需求

### 6.1 性能目标

以下均为目标值，最终以基准测试硬件和测量方法为准：

| 指标 | 目标 |
| --- | --- |
| 空闲工作集 | ≤ 25MiB |
| 动画期间工作集 | ≤ 40MiB |
| 峰值工作集 | ≤ 60MiB |
| 空闲 CPU | 连续 60 秒平均接近 0 |
| 触发响应时间 | Raw Input 触发至首次可见反馈 ≤ 50ms |
| 动画更新 | 目标 60 FPS；120Hz 屏幕不要求强制 120 FPS |

不得仅为了满足工作集数字而牺牲稳定性、可维护性或视觉流畅度。

### 6.2 可靠性与安全性

- Win32 窗口过程和 Raw Input 回调边界不得传播 C++ 异常。
- 所有 Win32、GDI、COM 资源使用 RAII 管理。
- 程序退出或渲染失败后不得留下黑色 Overlay。
- 渲染失败时应安全隐藏 Overlay，并保持托盘退出入口可用。
- Release 不使用 UPX 或自解压打包器。
- 构建产物包含版本资源；发布时提供 SHA-256 校验值。
- 正式企业分发可选代码签名，但未签名版本不承诺绕过企业执行策略。

## 7. 架构

```text
Win32 Application / Message Loop
├─ InstanceGuard
├─ TrayController
├─ RawInputSource
│  ├─ KeyboardState
│  ├─ DoubleCtrlDetector
│  └─ ShakeDetector
├─ ActivationController
├─ OverlayManager
│  ├─ MonitorProvider
│  ├─ OverlayWindow[]
│  └─ OverlayRenderer
├─ AnimationController
└─ ConfigLoader
```

设计约束：

- 手势检测为不依赖 HWND 的纯 C++ 模型，使用合成事件进行单元测试。
- 显示器枚举通过接口注入，允许在单屏机器模拟多屏拓扑。
- Overlay 管理与具体渲染后端分离，但第一版不为未实现的后端建立复杂插件系统。
- 主线程拥有窗口、托盘和渲染对象；后台线程不得直接操作 HWND。

## 8. 测试与验收

### 8.1 自动测试

- 左/右双 Ctrl 正常序列、超时、防抖、自动重复和左右混用。
- 自定义组合键完全匹配、额外修饰键、普通键占用和自动重复。
- `Ctrl+C`、`Ctrl+V`、Ctrl+Shift、左右 Ctrl 混用不得触发。
- 鼠标按钮按下期间及释放后的旧轨迹不得触发晃动。
- 快速单向跨屏移动不得识别为晃动。
- 多次方向反转、满足距离和比例时正确触发。
- 配置缺失、空文件、部分字段、非法字段和重新加载失败。
- 负坐标和混合 DPI 下的显示器/圆孔坐标转换。

测试使用 CTest 和仓库内轻量测试程序，不引入运行时第三方依赖。

### 8.2 单屏开发辅助

通过 `ZMouseShow.exe --simulate-displays` 提供普通窗口模拟模式，显示三块显示器、负坐标、纵向错位、100%/125%/150% DPI 和可跨屏移动的 120 DIP 高亮孔；数字键 1/2/3 分别切换圆形、圆角方形和菱形，可按 Esc 退出。模拟模式不启动托盘、Raw Input 或真实 Overlay，只验证布局、坐标映射、DPI 半径、形状与跨屏高亮孔，不能代替真实 DWM 多屏验收。

### 8.3 真实硬件验收矩阵

- 笔记本内屏 + 两块 2K 外接显示器。
- 主屏位于左、中、右三种布局。
- 负坐标、纵向错位和屏幕间空洞。
- 100% + 125%/150% 混合 DPI。
- 60Hz + 120Hz 混合刷新率。
- 插拔显示器、睡眠恢复、Explorer 重启。
- 普通桌面、RDP、HDR 和无边框全屏场景记录结果。

## 9. 构建与代码约束

- CMake 最低且指定版本：4.4。
- 生成器：`Visual Studio 18 2026`。
- MSVC 工具集：v145，64 位宿主工具，x64 目标。
- C++ 标准：C++23；不在 P0 使用 C++ Modules。
- Release 使用静态 CRT（`/MT`），Debug 使用 `/MTd`。
- 启用 `/W4`、`/permissive-`、`/Zc:__cplusplus`、`/utf-8`。
- 项目代码警告视为错误；Windows SDK 头文件警告不得污染项目目标。
- CMake 是唯一工程源；生成的 `.sln` 和 `.vcxproj` 不提交仓库。
- 支持从 VS 2026 打开文件夹，也支持 CMake Presets 命令行构建。

## 10. 迭代计划

每个阶段的软件功能、自动测试和约定放行范围完成后创建带说明的 annotated Git tag：`p0`、`p1`、`p2`。因硬件条件延后的兼容性矩阵必须在阶段验收清单中明确记录，不得伪造为已通过。

### P0：可用纵切

1. 工程、消息循环、单实例和托盘。
2. Raw Input 和纯净双击左 Ctrl 状态机。
3. 显示器枚举、Per-Monitor V2 和 Overlay 窗口。
4. Region 圆孔技术验证及脉冲环。
5. 内置配置、可选 TOML 和自动测试。

### P1：完整日常使用

1. 晃动检测和灵敏度调校。
2. 动画、显示器热插拔和 Explorer 恢复。
3. 右 Ctrl、自定义组合键、诊断信息导出。
4. 真实三屏兼容性验证；当前硬件不可用时记录为标签后的兼容性补测。
5. 单屏三屏拓扑模拟验收辅助。

### P2：体验增强

1. 完善原生设置对话框、触发源开关、快捷键冲突检测和安全回退。
2. 修复动画性能，增加高亮形状预设、放大光标副本、波纹和十字定位线。
3. 增加应用排除、全屏抑制和可选开机自启。
4. 完成多方案高压性能对比，并根据结果决定是否切换 DirectComposition 渲染后端。

### P3：稳定性与交互打磨

1. 修复晃动重新武装、触发请求去重和托盘/设置模态生命周期。
2. 统一孔洞、稳定描边和波纹形状，增加高对比十字线并避免双光标。
3. 增加晃动灵敏度、全局恢复默认和完整 TOML 设置持久化。
4. 增强运行状态诊断，完成真实桌面反馈回归并记录 Shell 层级与 XOR 光标限制。

### P4：局部放大与 GPU 渲染

1. 建立 DXGI Desktop Duplication + D3D11/Direct2D 捕获和局部合成路径。
2. 提供默认包含指针的局部放大镜，并允许独立启用或与暗化遮罩组合。
3. 提供镜片倍率、尺寸、形状、边缘曲率/描边等受约束设置，并保持点击穿透和不抢焦点。
4. 处理跨屏、混合 DPI、设备丢失、显示拓扑变化和安全降级；记录 HDR、RDP、受保护内容及递归捕获边界。
5. 保留轻量“只放大指针”功能至 P4 实测完成，再根据启动延迟、资源占用和可达性价值决定是否降级或移除。

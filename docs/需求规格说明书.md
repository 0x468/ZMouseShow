# ZMouseShow 需求规格说明书

文档版本：0.2（技术路线确认稿）  
目标平台：Windows 10 2004（Build 19041）及以上、Windows 11，x64  
构建环境：Visual Studio 2026、MSVC v145、CMake 4.4、C++23

## 1. 项目目标

ZMouseShow 是一个免安装、无管理员权限运行的 Windows 鼠标定位工具，主要解决笔记本连接多块高分辨率显示器后难以快速发现鼠标位置的问题。

程序通过纯净的双击左 Ctrl 手势或快速晃动鼠标触发定位效果：所有显示器短暂暗化，鼠标周围保留原始亮度，并显示醒目的脉冲效果。

### 1.1 核心目标

- 发布为原生 x64 单文件 `ZMouseShow.exe`。
- 不安装服务，不要求管理员权限，不写入 HKLM 注册表。
- 不依赖 .NET、WinUI Runtime、VC++ Redistributable 或第三方运行时 DLL。
- 正常输入必须继续传递给前台应用，程序不得拦截或修改键鼠事件。
- 适配负坐标、多显示器、混合 DPI、显示器热插拔和不同刷新率。
- 不记录按键内容、鼠标轨迹或遥测数据。

Windows 自带的系统 DLL 和图形组件不视为外部运行时依赖。

### 1.2 非目标

首个版本不承诺支持以下场景：

- UAC 安全桌面、锁屏界面和 `Ctrl+Alt+Del` 安全注意序列界面。
- 独占全屏程序、受保护视频内容或禁止桌面叠加的程序。
- 被企业 WDAC、AppLocker 或终端安全软件策略禁止执行未知 EXE 的环境。
- ARM64、Windows 10 Build 19041 以前的系统。
- 真正替换系统光标或修改系统光标方案。

## 2. 用户场景

典型环境为笔记本内屏加两块 2K、120Hz 外接显示器。显示器可能具有不同 DPI 缩放比例、不同刷新率，且主显示器不一定处于虚拟桌面的左上角。

程序应在普通用户权限下直接双击运行，驻留系统托盘。用户无需先创建配置文件即可使用默认行为。

## 3. 功能需求

### 3.1 程序生命周期

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| APP-001 | 同一用户会话只允许一个实例运行。 | P0 |
| APP-002 | 程序启动后驻留托盘，不显示主窗口，不抢占前台焦点。 | P0 |
| APP-003 | 托盘菜单提供暂停/恢复、重新加载配置、导出默认配置和退出。 | P0 |
| APP-004 | Explorer 重启后应恢复托盘图标。 | P1 |
| APP-005 | 显示器连接、断开、分辨率或 DPI 改变后重建 Overlay。 | P0 |

### 3.2 输入监听原则

键盘和鼠标输入使用 Raw Input（`WM_INPUT` + `RIDEV_INPUTSINK`）在后台观察，不使用 `WH_KEYBOARD_LL` 或 `WH_MOUSE_LL` 全局低级钩子。

- 不使用 `RIDEV_NOLEGACY`，不得阻止前台应用接收原始输入。
- 只在内存中维护当前按键/鼠标按钮状态、手势状态和短期相对位移。
- 不保存键值序列，不将输入写入日志或配置文件。
- 输入处理和渲染状态通过消息或事件解耦，Raw Input 处理不得执行耗时绘制。

### 3.3 双击左 Ctrl 触发

默认启用。合法手势为：

```text
左 Ctrl 按下 → 左 Ctrl 释放 → 左 Ctrl 按下（触发）→ 左 Ctrl 释放
```

必须同时满足：

- 第一次 Ctrl 按下前，没有其他键或任何鼠标按钮处于按下状态。
- 两次按键必须均为左 Ctrl；左右 Ctrl 独立处理。
- 两次按下间隔不超过系统 `GetDoubleClickTime()`，且不短于防抖下限。
- 手势期间没有其他键盘按键或鼠标按钮事件。
- 忽略键盘自动重复产生的重复按下事件。
- 触发后进入短暂冷却期，避免同一手势重复触发。

下列输入必须取消候选手势：

- `Ctrl+C`、`Ctrl+V`、`Ctrl+Shift+...` 等组合键。
- Alt、Win、右 Ctrl 或任意普通按键参与的输入。
- 左键、右键、中键、X1 或 X2 鼠标按钮按下。
- 第一、第二次 Ctrl 之间出现鼠标按钮事件。

取消候选手势不得吞掉或改变任何输入。

### 3.4 晃动鼠标触发

首个公开测试版本默认关闭，用户可在配置中启用。经过真实鼠标和触控板验证后再决定是否默认开启。

晃动检测使用 Raw Input 相对位移的滑动时间窗口，不使用单纯的屏幕像素位移阈值。判定至少考虑：

- 时间窗口内累计路径长度。
- 移动轨迹包围盒对角线。
- 累计路径与包围盒对角线的比值。
- 水平或垂直方向反转次数。
- 触发后的冷却时间。

以下情况禁止触发：

- 左、右、中、X1、X2 任意鼠标按钮处于按下状态。
- 任意鼠标按钮按下或释放的当前轨迹段。
- Overlay 已处于显示或淡出状态。
- 程序处于暂停状态。

任意鼠标按钮按下时必须立即清空晃动历史。全部按钮释放后也必须从新的移动轨迹开始累计，不能继承拖拽期间的位移。

### 3.5 定位效果

P0 默认效果为：

1. 所有有效显示器暗化。
2. 鼠标周围出现真正透明的圆孔，显示下面窗口的原始亮度。
3. 圆孔周围显示高对比度的收缩脉冲环。
4. 效果淡入并跟随鼠标。
5. 鼠标停止移动后自动淡出，并具有最大显示时长保护。

默认建议值：

| 设置 | 默认值 | 单位/说明 |
| --- | --- | --- |
| 圆孔半径 | 120 | DIP，按显示器 DPI 转换为物理像素 |
| 暗化不透明度 | 60 | 百分比 |
| 淡入/淡出时长 | 220 | ms |
| 静止自动关闭 | 1200 | ms |
| 最大显示时长 | 5000 | ms |
| 脉冲初始缩放 | 4.0 | 相对最终半径 |

下列行为立即启动淡出：

- Esc。
- 任意非触发键盘按键。
- 任意鼠标按钮按下；点击必须继续传递给下层窗口。
- 达到静止时间或最大显示时间。

触发手势自身剩余的左 Ctrl 释放事件不得立即关闭刚显示的效果。

### 3.6 可选视觉效果

| 效果 | 方案 | 优先级 |
| --- | --- | --- |
| 放大光标副本 | 通过 `GetCursorInfo` 获取当前 `HCURSOR`，在 Overlay 中绘制放大副本；不修改系统光标。 | P2 |
| 波纹 | 从鼠标位置扩散并淡出的同心圆。 | P2 |
| 十字定位线 | 在鼠标所在显示器绘制短暂高对比度定位线。 | P2 |
| 局部内容放大镜 | 捕获并放大鼠标附近屏幕内容。因 HDR、RDP、递归捕获和性能问题暂不实现。 | P3 |

不得通过 `SetSystemCursor` 修改全局系统光标。

## 4. Overlay 与渲染设计

### 4.1 窗口模型

- 每个有效显示器创建一个独立 Overlay 窗口。
- 窗口使用 `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW | WS_EX_TRANSPARENT | WS_EX_LAYERED`。
- 通过 `HWND_TOPMOST` 显示，不激活窗口；`WM_NCHITTEST` 返回 `HTTRANSPARENT`。
- 所有坐标在 Per-Monitor V2 感知下使用物理屏幕坐标，并显式处理虚拟桌面负坐标。
- 显示器拓扑变化后重新枚举显示器并原子替换窗口集合。

### 4.2 P0 混合渲染后端

首选技术验证方案：Window Region + 小型 per-pixel alpha 位图。

- 每块显示器使用恒定透明度的黑色 Overlay。
- 使用 Window Region 从 Overlay 中减去鼠标附近圆孔。
- 圆孔基础区域不需要显示器大小的 32 位位图。
- 仅为圆孔边缘、羽化和脉冲环维护一张数百像素大小的分层位图。
- 鼠标位于显示器边界时，对所有相交显示器应用相同全局圆孔。

必须先通过技术验证确认：

- Region 动画不存在明显闪烁或任务栏异常。
- 圆孔跨显示器边缘时没有明显接缝。
- 混合 DPI 和负坐标下圆心一致。
- 60Hz/120Hz 混合环境下动画节奏可接受。

如果该方案达不到视觉质量要求，保留相同的 Overlay 管理接口，替换为 Direct2D + DirectComposition 后端。不得直接依赖 WinUI 3 或 Windows App SDK Composition。

### 4.3 不采用全屏 GDI+ 位图的原因

三块 2560×1440 显示器横排时，单张 32 位虚拟桌面位图约占 42MiB；双缓冲、GDI 对象和逐帧内存复制会进一步增加资源消耗。全屏 `UpdateLayeredWindow` 不作为正式渲染方案。

## 5. 配置机制

P0 不提供设置窗口，使用内置默认值和可选 INI 文件。

### 5.1 配置加载规则

- 未找到配置文件：使用全部内置默认值。
- 空配置文件：使用全部内置默认值。
- 缺失字段：使用该字段的内置默认值。
- 格式错误或越界字段：忽略该字段并使用默认值。
- 重新加载失败：保留上一次完整有效配置。
- 未知字段：忽略，以支持前向兼容。
- 程序不得因为配置错误而退出或显示阻塞式错误框。

配置查找顺序：

1. 命令行 `--config <path>` 指定文件。
2. EXE 同目录的 `ZMouseShow.ini`。
3. 内置默认值。

程序首次运行不主动创建文件。托盘“导出默认配置”由用户显式触发。

### 5.2 设置界面计划

P1/P2 根据实际配置复杂度评估原生 Win32 模态设置对话框。设置界面不得成为 WinUI、WPF、WebView 或外部运行时的引入理由。

## 6. 非功能性需求

### 6.1 性能目标

以下均为目标值，最终以基准测试硬件和测量方法为准：

| 指标 | 目标 |
| --- | --- |
| 空闲工作集 | ≤ 25MiB |
| 动画期间工作集 | ≤ 40MiB |
| 峰值工作集 | ≤ 60MiB |
| 空闲 CPU | 连续 60 秒平均接近 0 |
| 触发响应时间 | Raw Input 触发至首次可见反馈 ≤ 50ms |
| 动画更新 | 目标 60 FPS；120Hz 屏幕不要求强制 120 FPS |

不得仅为了满足工作集数字而牺牲稳定性、可维护性或视觉流畅度。

### 6.2 可靠性与安全性

- Win32 窗口过程和 Raw Input 回调边界不得传播 C++ 异常。
- 所有 Win32、GDI、COM 资源使用 RAII 管理。
- 程序退出或渲染失败后不得留下黑色 Overlay。
- 渲染失败时应安全隐藏 Overlay，并保持托盘退出入口可用。
- Release 不使用 UPX 或自解压打包器。
- 构建产物包含版本资源；发布时提供 SHA-256 校验值。
- 正式企业分发可选代码签名，但未签名版本不承诺绕过企业执行策略。

## 7. 架构

```text
Win32 Application / Message Loop
├─ InstanceGuard
├─ TrayController
├─ RawInputSource
│  ├─ KeyboardState
│  ├─ DoubleCtrlDetector
│  └─ ShakeDetector
├─ ActivationController
├─ OverlayManager
│  ├─ MonitorProvider
│  ├─ OverlayWindow[]
│  └─ OverlayRenderer
├─ AnimationController
└─ ConfigLoader
```

设计约束：

- 手势检测为不依赖 HWND 的纯 C++ 模型，使用合成事件进行单元测试。
- 显示器枚举通过接口注入，允许在单屏机器模拟多屏拓扑。
- Overlay 管理与具体渲染后端分离，但第一版不为未实现的后端建立复杂插件系统。
- 主线程拥有窗口、托盘和渲染对象；后台线程不得直接操作 HWND。

## 8. 测试与验收

### 8.1 自动测试

- 双 Ctrl 正常序列、超时、防抖和自动重复。
- `Ctrl+C`、`Ctrl+V`、Ctrl+Shift、左右 Ctrl 混用不得触发。
- 鼠标按钮按下期间及释放后的旧轨迹不得触发晃动。
- 快速单向跨屏移动不得识别为晃动。
- 多次方向反转、满足距离和比例时正确触发。
- 配置缺失、空文件、部分字段、非法字段和重新加载失败。
- 负坐标和混合 DPI 下的显示器/圆孔坐标转换。

测试使用 CTest 和仓库内轻量测试程序，不引入运行时第三方依赖。

### 8.2 单屏开发辅助

提供调试模拟模式，在普通窗口中模拟三块显示器、负坐标和不同 DPI。该模式只验证状态、布局和坐标计算，不能代替真实 DWM 多屏验收。

### 8.3 真实硬件验收矩阵

- 笔记本内屏 + 两块 2K 外接显示器。
- 主屏位于左、中、右三种布局。
- 负坐标、纵向错位和屏幕间空洞。
- 100% + 125%/150% 混合 DPI。
- 60Hz + 120Hz 混合刷新率。
- 插拔显示器、睡眠恢复、Explorer 重启。
- 普通桌面、RDP、HDR 和无边框全屏场景记录结果。

## 9. 构建与代码约束

- CMake 最低且指定版本：4.4。
- 生成器：`Visual Studio 18 2026`。
- MSVC 工具集：v145，64 位宿主工具，x64 目标。
- C++ 标准：C++23；不在 P0 使用 C++ Modules。
- Release 使用静态 CRT（`/MT`），Debug 使用 `/MTd`。
- 启用 `/W4`、`/permissive-`、`/Zc:__cplusplus`、`/utf-8`。
- 项目代码警告视为错误；Windows SDK 头文件警告不得污染项目目标。
- CMake 是唯一工程源；生成的 `.sln` 和 `.vcxproj` 不提交仓库。
- 支持从 VS 2026 打开文件夹，也支持 CMake Presets 命令行构建。

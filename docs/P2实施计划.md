# ZMouseShow P2 实施计划

本文档定义 P2 的完整范围、分阶段提交边界和最终放行条件。每个阶段必须先完成对应自动测试与人工验证，再使用约定式提交合入；只有全部阶段通过后才创建 annotated tag `p2`。

状态：软件范围、真实单屏交互、高压基准和文档审计已完成；延后的三屏 120Hz 外部硬件矩阵见[P2 验收清单](P2验收清单.md)。

## 一、触发方式

双击 Ctrl、自定义组合键和晃动鼠标是三个可独立启用的触发源，不强制互斥。默认只启用双击左 Ctrl；同时启用多个触发源时，运行时仍只允许一个激活请求进入消息循环。

自定义组合键必须整组验证：

- 不允许单个普通键和常见业务组合键。
- 对已知 Windows 保留组合执行硬性拒绝或明确警告。
- 设置面板使用临时 `RegisterHotKey` 提前探测系统级占用；运行时持续持有已生效组合，避免其它程序随后抢占。不得宣称能够检测前台应用内部快捷键。
- 保存、加载或冲突检测失败时保留上一组有效配置；启动时无法采用自定义组合键时只禁用该触发源，双击 Ctrl 仍可作为回退。
- 设置面板提供恢复默认 `Ctrl+Alt+F11` 的操作；F12 按照 Windows 全局热键约束视为调试器保留键。

## 二、动画与渲染

先修复现有圆环缩放的逐帧位图重建问题，再增加视觉效果。基准工具必须能复现旧版全区域栅格化和候选实现，并输出平均帧耗时、P95、总耗时和表面内存。

生产实现的最低要求：

- 动画过程中不反复创建和销毁 DIB、DC 或窗口。
- 动画进度按时间计算，掉帧时允许跳过中间状态但不得延长锁屏式遮罩时间。
- 60Hz 与 120Hz 环境均记录帧间隔、CPU、工作集和最差帧。
- 最终对 Region + GDI 分层窗口、优化后的持久位图，以及可行的 Direct2D/DirectComposition 原型进行压力对比。

## 三、高亮形状与视觉效果

高亮孔洞形状必须是配置化预设，而不是写死为圆形。P2 内置：

- 圆形：默认值，保持现有行为。
- 圆角方形：适合较大的定位范围。
- 菱形：在密集界面中提供更强方向感。

形状只改变透明高亮区域的边界，不修改系统鼠标。圆环、波纹、十字定位线和放大光标副本作为可独立启用的视觉层；局部屏幕内容放大镜继续留在 P3。

实现状态：三个形状均通过同一 Region 工厂创建，已接入 TOML、诊断信息和原生设置面板；形状切换即时应用，默认值和旧配置保持圆形兼容。稳定圆环、向外扩散的启动波纹、十字定位线与 125%–400% 放大光标副本也已分别接入配置和设置面板。光标副本使用独立的小型分层窗口，不调用 `SetSystemCursor`，不会修改系统或其它程序的光标。

针对初版“大圆收缩”观感卡顿的问题，出现动画改为稳定圆环淡入加单次波纹扩散；动画期间预留最大尺寸的小型 DIB，不再逐帧调整分层窗口大小。最终是否满足混合 60Hz/120Hz 多屏环境仍以真实硬件补测为准。

## 四、应用排除与全屏抑制

“游戏模式”改为含义明确的“全屏抑制”：

- 关闭：所有场景均按普通规则工作。
- 自动：前台窗口覆盖整块显示器或捕获鼠标时，只抑制晃动触发，保留明确的键盘触发。
- 严格：全屏状态下抑制全部定位触发。

另提供按可执行文件名匹配的应用排除列表。全屏推断不是可靠的游戏识别，文档和界面不得将其描述为百分之百准确。开机自启使用普通用户范围方案，并明确企业策略可能阻止该操作。

实现状态：三档全屏抑制已通过独立策略核心接入四个实际触发入口；应用排除在策略判断前优先执行，并对 EXE 文件名进行规范化、去重和数量限制。设置面板可编辑模式、分号分隔的排除列表与登录自启动。自启动使用当前用户 `Run` 注册表值，设置保存失败会尝试恢复应用前状态；诊断报告同时记录期望值与实际注册状态。

## 五、阶段与提交边界

1. `perf:` 或 `refactor:` 修复圆环栅格化并建立基准。
2. `feat:` 完善触发源开关、快捷键编辑、冲突检测和回退。
3. `feat:` 增加高亮形状预设和视觉效果。
4. `feat:` 增加应用排除、全屏抑制与开机自启。
5. `feat:` 补齐设置面板与配置迁移。
6. `docs:` 完成中文使用说明、完整功能文档和性能对比报告。
7. `test:` 或 `chore:` 完成最终压力测试、发布检查与 P2 验收记录。

配置迁移采用兼容式补全，不要求用户手工修改旧文件：P1 TOML 缺少的 P2 表和字段按默认值加载，首次从设置面板保存时自动追加；原有注释、未知字段和未知表继续保留。保存前会解析并回读验证候选内容，任何解析、校验或原子替换失败都返回失败并保留原文件与当前运行时设置。

设置与配置阶段已通过真实原生窗口验证；验收中发现并修复了“十字定位线”和“排除程序”复用 `Alt+X` 的访问键冲突。Debug、Release 配置测试覆盖旧文件补全、注释和未知表保留、非法字段、无效语法、缺失文件以及失败保存不改写原文件。

性能与文档阶段已完成软件侧三轮高压基准、中文 README、使用说明、完整功能说明、汇总报告和原始 CSV。基准证明 Region + 持久 GDI 在三窗口 P95 的保守组合开销低于 120Hz 帧预算的 20%，因此 P2 不引入只有理想路径的 DirectComposition 半成品；触发重新评估的条件和未完成的真实多屏硬件矩阵已写入性能报告。

## 六、P2 放行条件

- Debug、Release 全量构建和 CTest 通过。
- 所有配置字段具有缺失、非法、保存失败和向前兼容测试。
- 单实例、托盘、设置面板、键盘导航和持久化完成真实交互验证。
- 至少在单屏模拟器和真实多屏环境分别完成视觉验证；缺少的硬件矩阵必须明确记录为待补测，不能记为通过。
- 性能报告包含测试硬件、构建类型、场景、样本数量、原始结果、限制和结论。
- 仓库项目文档统一为中文；第三方许可证和上游原始文件不改写。
- 工作区干净，提交历史按模块分段，最后创建带说明的 annotated tag `p2`。

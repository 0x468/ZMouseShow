# ZMouseShow P2 实施计划

本文档定义 P2 的完整范围、分阶段提交边界和最终放行条件。每个阶段必须先完成对应自动测试与人工验证，再使用约定式提交合入；只有全部阶段通过后才创建 annotated tag `p2`。

## 一、触发方式

双击 Ctrl、自定义组合键和晃动鼠标是三个可独立启用的触发源，不强制互斥。默认只启用双击左 Ctrl；同时启用多个触发源时，运行时仍只允许一个激活请求进入消息循环。

自定义组合键必须整组验证：

- 不允许单个普通键和常见业务组合键。
- 对已知 Windows 保留组合执行硬性拒绝或明确警告。
- 可使用临时 `RegisterHotKey` 探测已有的系统级全局占用，但不得宣称能够检测前台应用内部快捷键。
- 保存、加载或冲突检测失败时保留上一组有效配置；启动时无法采用自定义组合键时只禁用该触发源，双击 Ctrl 仍可作为回退。
- 设置面板提供恢复默认 `Ctrl+Alt+F12` 的操作。

## 二、动画与渲染

先修复现有圆环缩放的逐帧位图重建问题，再增加视觉效果。基准工具必须能复现旧版全区域栅格化和候选实现，并输出平均帧耗时、P95、总耗时和表面内存。

生产实现的最低要求：

- 动画过程中不反复创建和销毁 DIB、DC 或窗口。
- 动画进度按时间计算，掉帧时允许跳过中间状态但不得延长锁屏式遮罩时间。
- 60Hz 与 120Hz 环境均记录帧间隔、CPU、工作集和最差帧。
- 最终对 Region + GDI 分层窗口、优化后的持久位图，以及可行的 Direct2D/DirectComposition 原型进行压力对比。

## 三、高亮形状与视觉效果

高亮孔洞形状必须是配置化预设，而不是写死为圆形。P2 内置：

- 圆形：默认值，保持现有行为。
- 圆角方形：适合较大的定位范围。
- 菱形：在密集界面中提供更强方向感。

形状只改变透明高亮区域的边界，不修改系统鼠标。圆环、波纹、十字定位线和放大光标副本作为可独立启用的视觉层；局部屏幕内容放大镜继续留在 P3。

## 四、应用排除与全屏抑制

“游戏模式”改为含义明确的“全屏抑制”：

- 关闭：所有场景均按普通规则工作。
- 自动：前台窗口覆盖整块显示器或捕获鼠标时，只抑制晃动触发，保留明确的键盘触发。
- 严格：全屏状态下抑制全部定位触发。

另提供按可执行文件名匹配的应用排除列表。全屏推断不是可靠的游戏识别，文档和界面不得将其描述为百分之百准确。开机自启使用普通用户范围方案，并明确企业策略可能阻止该操作。

## 五、阶段与提交边界

1. `perf:` 或 `refactor:` 修复圆环栅格化并建立基准。
2. `feat:` 完善触发源开关、快捷键编辑、冲突检测和回退。
3. `feat:` 增加高亮形状预设和视觉效果。
4. `feat:` 增加应用排除、全屏抑制与开机自启。
5. `feat:` 补齐设置面板与配置迁移。
6. `docs:` 完成中文使用说明、完整功能文档和性能对比报告。
7. `test:` 或 `chore:` 完成最终压力测试、发布检查与 P2 验收记录。

## 六、P2 放行条件

- Debug、Release 全量构建和 CTest 通过。
- 所有配置字段具有缺失、非法、保存失败和向前兼容测试。
- 单实例、托盘、设置面板、键盘导航和持久化完成真实交互验证。
- 至少在单屏模拟器和真实多屏环境分别完成视觉验证；缺少的硬件矩阵必须明确记录为待补测，不能记为通过。
- 性能报告包含测试硬件、构建类型、场景、样本数量、原始结果、限制和结论。
- 仓库项目文档统一为中文；第三方许可证和上游原始文件不改写。
- 工作区干净，提交历史按模块分段，最后创建带说明的 annotated tag `p2`。

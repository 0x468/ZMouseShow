# ZMouseShow P2 渲染性能对比报告

状态：P2 软件基准完成；目标用户的“笔记本内屏 + 两块 2K 120Hz 17 寸显示器”真实硬件主观验收仍待补测，本文不把单屏开发机结果冒充为该硬件结论。

## 一、结论

P2 保留 Region + 持久 GDI 分层窗口方案，不引入 Direct2D/DirectComposition 生产管线。

- 圆环只处理圆周覆盖范围后，常用 96–200 DPI 场景平均快 6.59–10.50 倍，P95 快 10.40–15.03 倍；最大允许半径平均快 16.34 倍。
- 三个分层窗口连续更新 480 帧时，持久 DIB 三轮中位平均耗时为 0.564 ms/帧、P95 为 0.698 ms；逐帧重建 DIB 分别为 1.081 ms 和 1.345 ms。
- 三个全屏尺寸 Region 孔洞连续移动的三轮中位平均耗时为 0.636 ms/帧、P95 为 0.960 ms。
- 将三窗口持久 DIB 与三窗口 Region 的 P95 保守相加为 1.658 ms，占 120Hz 的 8.333 ms 帧预算约 19.9%。实际生产动画不会在每帧同时重建三个全屏 Region，因此这是偏保守的上界。
- 预热后各场景 GDI 对象和进程句柄变化均为 0；USER 对象偶有 1 个瞬时差异，没有随窗口数或轮次单调增长。

当前卡顿的主要来源已不是圆环 CPU 绘制，而更可能是 DWM 调度、混合刷新率、远程桌面、驱动或主观动画设计。P2 已将“大圆收缩”改为稳定圆环淡入加单次向外波纹，避免缩放方向造成的视觉跳动。

## 二、测试环境

- 操作系统：Windows 11 专业版，Build 26200；
- 处理器：Intel Core i5-13600K，14 核 20 线程；
- 内存：约 64 GiB；
- 显卡：NVIDIA GeForce RTX 4060 Ti；系统同时存在 Oray 虚拟显示适配器；
- 编译器：Visual Studio 2026、MSVC v145；
- CMake：4.4 系列工程配置；
- 构建类型：Release，静态 CRT；
- 运行方式：每项先预热，再连续执行三轮独立进程。

本机运行基准时没有用户目标中的三块物理显示器。Win32 叠加层基准用 1、2、3 个离屏但真实创建的分层窗口模拟提交数量，调用实际 `UpdateLayeredWindow`、`SetWindowRgn`、DIB/DC 和 GDI 对象 API；它可以测 CPU 提交与资源生命周期，但不能测三块物理扫描输出的最终呈现抖动。


## 四、Region + GDI 与 Direct2D/DirectComposition

| 维度 | 当前 Region + 持久 GDI | Direct2D/DirectComposition |
| --- | --- | --- |
| 当前 P2 图形 | 圆环、波纹、短十字线和透明孔洞足够直接 | 能实现，但优势有限 |
| 全屏暗化内存 | Region 表示孔洞，不需要每屏 RGBA 表面 | 通常需要交换链/表面和合成树 |
| 小型特效提交 | 三窗口 P95 0.698 ms | 预期 GPU 合成更强，但本报告未伪造未执行的实测值 |
| 动画同步 | 8 ms 等待定时器，不与垂直同步绑定 | 可由合成器调度，更适合持续动画 |
| 复杂效果 | 手工预乘 Alpha，适合有限预设 | 渐变、模糊、变换和内容放大更自然 |
| 故障面 | GDI/DWM 路径成熟，远程会话行为较简单 | 需要 COM、D3D/DXGI 设备、设备丢失和驱动回退 |
| 体积与维护 | 当前代码和系统库足够 | 系统 DLL 无需随包分发，但代码、链接和测试矩阵显著增加 |

本阶段没有提交一个只为“跑分”而存在、却不具备设备丢失和远程会话回退的 DirectComposition 半成品，因此不报告虚假的 D2D 数字。现有生产路径在最保守三窗口 P95 上仍有约 80.1% 的 120Hz CPU 帧预算余量，迁移收益不足以覆盖新增故障面。

以下任一条件出现时应在 P3 重新建立 DirectComposition 原型并做同机 A/B：

- 加入实时局部屏幕放大镜、模糊或连续缩放；
- 真实三屏 120Hz 测得 DWM 提交或呈现 P95 超过 4 ms；
- 动画需要严格垂直同步，当前等待定时器产生可见节拍差；
- Region 在目标驱动、远程桌面或特殊全屏程序中出现兼容问题。

## 五、资源与泄漏观察

Win32 基准在进程内预热后记录每个场景前后快照。三轮中 GDI 对象变化均为 0，句柄变化均为 0；USER 对象只有个别轮次出现 1 的瞬时差异，没有随帧数、窗口数或轮次增长。工作集约有 0–3.6 MiB 波动，私有字节变化约 0–0.012 MiB，且 Region 场景会因系统回收出现负变化，因此不能把单次工作集差值解释为泄漏。

自动测试之外，最终真实多屏验收仍应在任务管理器或 Process Explorer 中循环触发至少 10 分钟，确认 GDI、USER、句柄和工作集达到稳态。

# ZMouseShow 渲染性能对比报告

状态：阶段性报告，P2 完成前继续补充。当前结果只比较圆环 CPU 栅格化算法，不能代表完整 Overlay 的端到端性能。

## 一、测试环境

- 操作系统：Windows 11 专业版，Build 26200。
- 处理器：Intel Core i5-13600K，14 核 20 线程。
- 内存：约 64 GiB。
- 显卡：NVIDIA GeForce RTX 4060 Ti；系统同时存在 Oray 虚拟显示适配器。
- 编译器：Visual Studio 2026、MSVC v145。
- 构建类型：Release，静态 CRT。
- 基准命令：`zmouse_render_benchmark.exe --animations 50`。

## 二、被比较方案

### 旧版全区域栅格化

每一帧按照当前圆环尺寸重新分配像素表面，遍历完整矩形区域，对每个像素执行距离计算。生产旧实现还会逐帧创建和销毁 DIB、内存 DC，因此本基准低估了旧版真实开销。

### 持久表面圆周栅格化

按照动画最大尺寸只分配一次像素表面。每一帧沿圆环覆盖范围擦除旧圆环并绘制新圆环，工作量主要随圆周和描边宽度增长，不再随矩形面积增长。生产实现复用同一个 DIB 和内存 DC。

## 三、阶段性数据

每组运行 50 次完整动画，每次 14 帧，共 700 帧。

| 场景 | 方案 | 总耗时 | 平均每帧 | P95 每帧 | 峰值表面内存 |
| --- | --- | ---: | ---: | ---: | ---: |
| 96 DPI、120 px 基准半径 | 旧版全区域栅格化 | 802.003 ms | 1121.371 µs | 4137.900 µs | 3.784 MiB |
| 96 DPI、120 px 基准半径 | 持久表面圆周栅格化 | 73.986 ms | 105.651 µs | 211.800 µs | 3.784 MiB |
| 150% DPI、180 px 基准半径 | 旧版全区域栅格化 | 1835.331 ms | 2562.106 µs | 9279.500 µs | 8.515 MiB |
| 150% DPI、180 px 基准半径 | 持久表面圆周栅格化 | 127.343 ms | 181.878 µs | 365.900 µs | 8.515 MiB |

阶段性结论：

- 96 DPI 场景平均帧约快 10.6 倍，P95 约快 19.5 倍。
- 150% DPI 场景平均帧约快 14.1 倍，P95 约快 25.4 倍。
- 两种算法使用相同最大像素表面，因此动画峰值表面内存没有下降；生产实现会在缩放结束后收缩为基础半径表面，避免长期保留峰值画布。
- 输出校验和一致；自动测试还会逐像素比较多组半径和描边，保证优化栅格器与旧算法输出一致。

## 五、当前限制

- 当前机器没有用户目标中的笔记本内屏加两块 2K 120Hz 显示器环境。
- 本轮 Windows 自动化可视验证授权超时，尚未形成优化后真实动画的自动截图证据。
- `WM_TIMER` 的 16 ms 周期理论上约为 60 FPS，并不与 DWM 或 120Hz 刷新同步；即使 CPU 栅格化已明显变快，后续仍需评估更稳定的帧调度或 DirectComposition 动画。

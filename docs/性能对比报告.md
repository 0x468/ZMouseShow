# ZMouseShow 渲染性能对比报告

状态：阶段性报告，P2 完成前继续补充。当前结果只比较圆环 CPU 栅格化算法，不能代表完整 Overlay 的端到端性能。

## 一、测试环境

- 操作系统：Windows 11 专业版，Build 26200。
- 处理器：Intel Core i5-13600K，14 核 20 线程。
- 内存：约 64 GiB。
- 显卡：NVIDIA GeForce RTX 4060 Ti；系统同时存在 Oray 虚拟显示适配器。
- 编译器：Visual Studio 2026、MSVC v145。
- 构建类型：Release，静态 CRT。
- 基准命令：`zmouse_render_benchmark.exe --animations 50`。

## 二、被比较方案

### 旧版全区域栅格化

每一帧按照当前圆环尺寸重新分配像素表面，遍历完整矩形区域，对每个像素执行距离计算。生产旧实现还会逐帧创建和销毁 DIB、内存 DC，因此本基准低估了旧版真实开销。

### 持久表面圆周栅格化

按照动画最大尺寸只分配一次像素表面。每一帧沿圆环覆盖范围擦除旧圆环并绘制新圆环，工作量主要随圆周和描边宽度增长，不再随矩形面积增长。生产实现复用同一个 DIB 和内存 DC。

## 三、阶段性数据

当前动画从 2.25 倍半径收缩到基础半径，180 ms 内按 8 ms 调度目标生成 24 帧。每组运行 50 次完整动画，共 1200 帧。

| 场景 | 方案 | 总耗时 | 平均每帧 | P95 每帧 | 峰值表面内存 |
| --- | --- | ---: | ---: | ---: | ---: |
| 96 DPI、120 px 基准半径 | 旧版全区域栅格化 | 615.272 ms | 509.100 µs | 1245.200 µs | 1.266 MiB |
| 96 DPI、120 px 基准半径 | 持久表面圆周栅格化 | 94.640 ms | 78.829 µs | 120.300 µs | 1.266 MiB |
| 150% DPI、180 px 基准半径 | 旧版全区域栅格化 | 1494.542 ms | 1221.705 µs | 2833.100 µs | 2.848 MiB |
| 150% DPI、180 px 基准半径 | 持久表面圆周栅格化 | 157.116 ms | 130.880 µs | 199.900 µs | 2.848 MiB |

阶段性结论：

- 96 DPI 场景平均帧约快 6.5 倍，P95 约快 10.4 倍。
- 150% DPI 场景平均帧约快 9.3 倍，P95 约快 14.2 倍。
- 两种算法使用相同最大像素表面，因此动画峰值表面内存没有下降；生产实现会在缩放结束后收缩为基础半径表面，避免长期保留峰值画布。
- 输出校验和一致；自动测试还会逐像素比较多组半径和描边，保证优化栅格器与旧算法输出一致。
- 当前持久表面方案的 P95 CPU 栅格化耗时约为 0.12 ms 和 0.20 ms，明显低于 8 ms 的动画帧预算；后续端到端报告仍需计入窗口合成和系统调度。

## 四、动画调度调整

- 原实现使用 16 ms 的低优先级 `WM_TIMER`，理论上限约 60 FPS，并且消息队列繁忙时会继续延后。
- 当前实现在动画出现和消失期间启用 8 ms 高精度等待定时器，由消息循环同时等待定时器与窗口消息；稳定显示后立即取消，不产生持续唤醒。
- 不支持高精度等待定时器的系统会回退到普通等待定时器；若创建或启动失败，再回退到 `WM_TIMER`。
- 动画仍按单调时钟计算进度，因此某一帧延迟不会拖长总动画时长，也不会累积位置误差。

## 六、当前限制

- 当前机器没有用户目标中的笔记本内屏加两块 2K 120Hz 显示器环境。
- 已通过 Windows 自动化验证触发、稳定显示和按键淡出，并捕获到淡出中的中间帧；自动截图只能验证状态连续推进，不能代替 120 Hz 环境下的主观流畅度测试。
- 8 ms 等待定时器并不与 DWM 垂直同步，最终仍需测量实际帧间隔，并与 DirectComposition 动画原型比较。
